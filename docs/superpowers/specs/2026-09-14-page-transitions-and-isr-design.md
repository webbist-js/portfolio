# Page transitions + ISR with on-demand revalidation

Date: 2026-09-14

## Goal

Two polish items for the portfolio, shipped together:

1. Route changes animate instead of hard-cutting, using the browser View Transitions API.
2. Content pages are served from Vercel's edge cache (ISR) and purged the moment
   content is published in Strapi, instead of re-rendering against Strapi Cloud on
   every request.

## Current state

- Every page is SSR on demand (adapter-auto → Vercel serverless). No cache headers.
  Only the GitHub feed has a 5‑minute in-process cache.
- No route transitions. The global `prefers-reduced-motion` rule in `base.css` uses
  `*`, which does not match `::view-transition-*` pseudo-elements.
- Backend: Strapi 5.53, schemas generated by a script; no lifecycle or document
  middleware code yet. Public read permissions are granted in `src/index.ts` from a
  `PUBLIC_READ_APIS` list.

## Part A — Page transitions

### Mechanism

`onNavigate` from `$app/navigation` in `+layout.svelte`:

```ts
onNavigate((navigation) => {
	if (!document.startViewTransition) return;
	if (navigation.from?.url.pathname === navigation.to?.url.pathname) return; // hash/query only
	if (matchMedia('(prefers-reduced-motion: reduce)').matches) return;
	return new Promise((resolve) => {
		document.startViewTransition(async () => {
			resolve();
			await navigation.complete;
		});
	});
});
```

Progressive enhancement: browsers without the API navigate as today. No deps.

### What moves

Named view-transition groups so the shell stays still:

| Element | `view-transition-name` | Animation |
| --- | --- | --- |
| `.status-strip`, `.site-header`, `.site-footer` | `status`, `header`, `footer` | none (pinned; identical snapshots) |
| `main` | `main` | old: fade out 160ms ease-in · new: fade in + rise 8px→0, 240ms `--ease-out` |
| `root` | (default) | animation disabled |

Shared-element titles (option chosen by the user): the title text in list rows and
the `h1` on the matching detail page share `view-transition-name: title-<slug>`, so
the title morphs from list to article/case study and back.

- Set on: `ProjectRow` name, the writing-index article title (row and featured
  card), `work/[slug]` h1, `writing/[slug]` h1.
- A name must be unique per page. The implementation dedupes by slug where the same
  item can render twice (e.g. featured + list on the same page): only the first
  occurrence carries the name.
- Names are plain CSS idents: slugs are already kebab-case; prefix `title-`.
- Externally published articles link out, so their names never match anything;
  harmless.

### Reduced motion

JS skip above, plus a CSS belt in `base.css`:

```css
@media (prefers-reduced-motion: reduce) {
	::view-transition-group(*),
	::view-transition-old(*),
	::view-transition-new(*) { animation: none !important; }
}
```

### Accessibility / e2e

No DOM or aria changes. Focus management and scroll restoration remain SvelteKit's.
axe suite unaffected. Playwright's Chromium supports view transitions; existing e2e
navigation assertions await load state, not animation.

## Part B — ISR + on-demand revalidation

### Frontend

**Adapter.** Replace `@sveltejs/adapter-auto` with `@sveltejs/adapter-vercel`
(explicit; needed for the typed `isr` route config). Runtime default.

**Route config.** `src/lib/server/isr.ts`:

```ts
import { BYPASS_TOKEN } from '$env/static/private';
export const isr = (expiration: number | false = 3600) => ({
	isr: { expiration, bypassToken: BYPASS_TOKEN, allowQuery: [] as string[] }
});
```

Applied via `export const config = isr()` in the seven content page loaders:
`/`, `/work`, `/work/[slug]`, `/services`, `/writing`, `/writing/[slug]`, `/about`.
Homepage uses `isr(300)` so the GitHub feed keeps its 5‑minute freshness. The hourly
fallback elsewhere is a safety net if a purge is ever lost.

`allowQuery: []` means query strings do not fragment the cache. SvelteKit's
`__data.json?x-sveltekit-invalidated=…` requests therefore share one entry; safe
here because the client always holds root-layout data and no route calls
`invalidate()`.

Not ISR: `/api/book-call` (POST), `/api/revalidate`, `sitemap.xml`, `robots.txt`.

`/about` has a form action. Vercel prerender functions serve GET/HEAD from cache
and invoke the function for other methods, so the POST still runs. This is the one
behaviour to confirm with a single manual submission after the first deploy.

**Revalidation endpoint.** `src/routes/api/revalidate/+server.ts` (POST):

- Auth: `Authorization: Bearer <REVALIDATE_SECRET>` (dynamic private env).
  503 if the secret is not configured, 401 on mismatch.
- Body: `{ entries: Array<{ model: string; slug?: string }> }` (batched).
- Computes affected paths with a pure `pathsFor(entries, slugs)` from
  `src/lib/server/revalidate.ts`, fetching current project/article slug lists from
  Strapi only when an entry needs them.
- Each path expands to `path` and its data path (`/__data.json` or
  `${path}/__data.json`). Deduped, capped at 200 paths.
- Fires `GET ${PUBLIC_SITE_URL}${path}` with header
  `x-prerender-revalidate: BYPASS_TOKEN` for each, via `Promise.allSettled`.
- Responds `{ revalidated: string[], failed: string[] }`.
- Outside Vercel (local dev) the fetches just re-render; harmless.

**Model → path map** (derived from which loaders call which getters):

| model | paths |
| --- | --- |
| global | every page incl. all project and article details |
| homepage | `/` |
| project | `/`, `/work`, all `/work/<slug>` (detail "next" links depend on the list) |
| article, topic | `/`, `/writing`, all `/writing/<slug>` |
| service, process-phase, faq, testimonial | `/`, `/services` |
| experience, principle, book | `/about` |
| activity | `/`, `/about` |
| anything else | none |

A unit test pins this table.

**Env (frontend).** `BYPASS_TOKEN` (static private — the build and svelte-check
fail without it, like the public vars), `REVALIDATE_SECRET` (dynamic private).
Added to `.env.example`, the CI workflow `env` block (dummy values), and Vercel.

### Backend

`strapi.documents.use(...)` — Strapi 5's document-service middleware, the successor
to per-content-type lifecycles for publish/unpublish semantics — registered in
`register()` of `src/index.ts`; logic in `src/revalidate.ts`.

Trigger rule for a uid in `PUBLIC_READ_APIS`:

- `publish`, `unpublish`, `delete` → always.
- `create`, `update` → only if the content type has no `draftAndPublish`, or the
  call carries `status: 'published'`. Saving a draft never purges.
- `discardDraft` → never (published content unchanged).

Entries `{ model, slug? }` (slug from result or params when the type has one) are
coalesced for 1.5s in-process and sent as one POST to `FRONTEND_REVALIDATE_URL` with
the bearer secret. Fire-and-forget after `next()`: never blocks or fails the admin
action; failures go to `strapi.log.warn`.

No-op (single startup info log) when `FRONTEND_REVALIDATE_URL` or
`REVALIDATE_SECRET` is unset, which is the local-dev default.

**Env (backend).** `FRONTEND_REVALIDATE_URL`, `REVALIDATE_SECRET` in `.env.example`
and Strapi Cloud.

### Failure modes

- Purge request fails → page stays cached until the hourly (homepage 5‑min)
  expiration. Logged on both sides.
- Strapi unreachable during a purge that needs slug lists → those entries fall back
  to index pages only; response lists them under `failed`.
- Wrong secret → 401, logged in Strapi.

## Testing

- Vitest (server project): `pathsFor` table + data-path expansion + cap;
  bearer-auth helper.
- `npm run check` in both workspaces; `npm run lint` before commit.
- Local: `curl` the endpoint (401 without secret, 200 with, response lists paths).
  Restart Strapi dev with the two env vars pointed at `localhost:5173`, publish a
  project via `strapi-local` MCP, observe the frontend log the purge.
- Full e2e + axe once immediately before push.
- After first deploy (user): edit the availability note in Strapi Cloud, then request
  the affected page and check the `x-vercel-cache` header goes MISS/REVALIDATED (the
  Strapi log line alone does not prove the purge reached Vercel); submit the About
  contact form once and the Writing newsletter form once (both routes are ISR with
  form actions).

## Before deploying (user action — not automatable from here)

1. Vercel project env: `BYPASS_TOKEN` (random, ≥32 chars), `REVALIDATE_SECRET`.
2. Strapi Cloud env: `FRONTEND_REVALIDATE_URL=https://www.alex-bennett.co.uk/api/revalidate`,
   `REVALIDATE_SECRET` (same value as Vercel).
3. Local `frontend/.env.local`: add `BYPASS_TOKEN=dev` so svelte-check/build pass.

Push only after step 1, or the Vercel build fails on the missing static env var.
